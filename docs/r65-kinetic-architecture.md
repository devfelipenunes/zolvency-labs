## Why R64 is not yet art-directed
Reading implementation in src/graphics/glyphChoreography.js, glyphRig.js and spatialNarrativeText.js: every glyph has transform and opaque depth-tested geometry; title/body each use one merged dynamic mesh. But the composition follows camera quaternion and a fixed .50 world-unit depth, not the facility. Across acts, offsets are largely screen-relative, enter/exit mirror similar patterns; each act switches group rather than maintaining character continuity. Text uses Helvetiker with precomputed vertex colors in MeshBasicMaterial, so edge luminance does not change naturally with light and rotation. CPU rewrites positions while moving, without rotating normals, so simply replacing with lit material would be incorrect. These are code observations, not a verified visual verdict or phone profile.

## Visual direction — precision machinery, sculptural type
Reference palette (proposed): graphite #11191D, mineral ivory #DEE8E1, titanium #899A98, muted green #67BFA1. Title Space Grotesk Semibold candidate, body Space Grotesk Medium or Inter Medium; render swatches rather than choose on name alone. Upper/lower case as approved. Title thickness .10–.16 cap height, bevel .01–.025 cap height; body .04–.07 cap height with restrained bevel. Mineral ceramic title with satin graphite sides, subtle green edge reflection only when directionally lit. One shared material family, no global bloom, no fake RGB separation, no duplicate logos/copy, no fade, no excessive noise. Static reading baseline, comfortable letter spacing and preserved kerning. Composition 2–3 title lines and short body, do not force body to animate at same amplitude as title. Physical environment lights or limited text-specific analytical lighting; verify no effect on facility.

## Seven acts: each is a physical event, not a generic stagger
1. ORIGIN — Beyond the known. Letters enter via hangar structural axes and gather from near/far to form a single elevated word sculpture. Camera passes a real foreground structural edge; letter group revealed through depth. Body assembles in a calmer secondary plane.
2. BLOCKCHAIN — Trust by design. Carriage-like lateral transport along rack front, successive contacts transfer an impulse through glyph neighbors. Compress spacing briefly then exact rest. Depart along server aisle. Test convex compound colliders in isolated offline bake.
3. INFRASTRUCTURE — Built for scale. Three depth layers enter like rack modules; letters rotate around local vertical axis to dock, one row becomes two, then unified baseline. No public network name.
4. CRYPTOGRAPHY — Verify without revealing. Interlocking approach through the security threshold; precise glyph rotations and alignment, read in stable composition. Use real occlusion at doorway, no alpha or random scrambling.
5. INTELLIGENCE — Intelligence in motion. Traveling impulse follows the console's curve; sequential letters lift, arc and settle, like a signal propagating through a system. Body restrained.
6. QUANTUM — Beyond classical limits. Distinct orbital paths around cryostat (not through it), alternating depth and angular momentum, synchronized convergence at .935 hold. No physical quantum-mechanics claims.
7. CONVERGENCE — Engineering what comes next. Reuse compatible glyphs from previous composition; converge toward one monumental final lock. Keep final readable and reversible. Single brand mark, no duplication.

## Motion engine proposal
Offline authoring: glyph atlas -> text shaping + per-glyph ID -> rest poses -> path planner (Bezier/Catmull-Rom, quaternion slerp, named anticipation/impulse/settle segments) -> optional fixed-timestep rigid-body proxy simulation, capture trajectories and contact evidence -> deterministic correction to exact layout -> baked TRS tracks. At runtime, map existing rendered camera progress p to authored tracks; no wall-clock timer or live physics. Forward/reverse/pause same pose at same p. Do not reset native gesture ownership. Match recurring letters across consecutive phrases by minimum travel subject to equal glyph identity, stable tie breaks; unmatched exit behind actual scenery or outside frame, new glyphs enter from authored anchors. Cross-act coexistence must have bounded object count; never overlay two fully readable copies. No opacity interpolation; existing optical cut retained.

Fixed world-space anchor candidates derived from actual R60 camera and geometry. Use existing exportBlenderPrevis/inspectLayout, raycasts and BVH to identify visible surfaces and clear movement corridor. Author separate mobile/desktop framing; near-camera plane only as explicitly experimental control, never call it wall-mounted. Sample title bounds and every glyph path, detect real scene intersections with opaque equipment and approximate letter-letter contacts. Record actual occluder and sample coverage; no claim of continuous collision proof from sampled test. Exact hold projection, orientation and contrast; no text motion during hold.

## Renderer A/B
A: R64 CPU deformation control. B: BatchedMesh with cached glyph geometry and per-letter matrix. C: merged static geometry with glyph index/pivot attributes and transform palette (vertex shader / DataTexture), rotate normals with same transform; compare cost on actual r180 WebGL2. D: InstancedMesh per glyph class if batching unavailable or faster. Shared physical material or cheap normal-aware material; don't add scene lights or postprocessing before profiling. Keep two logical roles; actual draw submissions measured. Cache all glyph meshes and tracks before loader reveal; compare CPU time, data uploads, draw submissions, GPU memory proxy and p95 device frame intervals. Reject runtime rebuild, new scroll listener or separate RAF.
